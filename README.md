# Ninja take-home: starter repo

This repo gives you the plumbing for the Buddy take-home, so your time goes into the parts we want to see. Read the assessment brief first; this README only covers what is already here.

You may change anything: rename, restructure, swap Bun for Node, or replace a library. If you do, say why in `NOTES.md`.

## Run it

```sh
docker compose up --build
```

| Service | URL | What's there now |
|---|---|---|
| Gateway (Bun + Elysia) | http://localhost:3000 | `GET /health`, `GET /health/db` |
| AI service (FastAPI) | http://localhost:8001 | `GET /health` |
| Postgres 16 | `postgres://ninja:ninja@localhost:5432/ninja` | Schema and seed data |

The database is created from `db/init/` on the first start only. To reset it, run `docker compose down -v`.

Run the tests outside Docker:

```sh
cd gateway && bun install && bun test
cd ai-service && uv sync && uv run pytest
```

## What's provided

| Path | Contents |
|---|---|
| `db/init/001_schema.sql` | `users`, `pets`, `activity_daily` |
| `db/init/002_seed.sql` | 4 users, 3 pets, 14 days of activity per pet (generated by `tools/generate_seed.py`) |
| `data/activity_daily.csv` | The same activity data as CSV |
| `fixtures/tokens.json` | Stub bearer tokens, one per user |
| `knowledge/` | 20 short vet articles with front matter (`id`, `title`, `species`, `topics`) |
| `ai-service/src/ai_service/llm.py` | `LLMProvider` interface and `FakeLLMProvider` |
| `ai-service/src/ai_service/knowledge.py` | Loads and parses the knowledge pack |
| `gateway/src/app.ts` | Elysia app factory with a Postgres client injected |

Chat turns, reviews and audit entries are **not** in the schema. Designing them is part of the task. Add your own migrations; any tool is fine.

## The fake LLM

`FakeLLMProvider` makes no network calls, and the same input always gives the same output. Use it in tests.

- **Citations:** it cites every `[source:<article-id>]` tag it finds in the messages. Put that tag next to each article you include in the prompt.
- **Streaming:** `stream()` yields the answer word by word. `complete()` returns it whole.
- **Failure switches:** put one of these in the user's message to test failure paths without mocks.

| Phrase | Effect |
|---|---|
| `[[fake:error]]` | Raises `ProviderUnavailableError` |
| `[[fake:slow]]` | Waits `FAKE_SLOW_SECONDS` (default 12) before answering |
| `[[fake:refuse]]` | Adds a line recommending a human painkiller, which your checks should catch |

To use a real model, add a provider in `get_provider()` and select it with `LLM_PROVIDER`. That's optional.

## The knowledge pack

The articles were written for this exercise. They are general and cautious, and they have not been reviewed by a vet. Don't use them outside this task.

Emergency articles say **"Contact a vet now"**. Your red-flag handling should not depend on that phrase alone.
